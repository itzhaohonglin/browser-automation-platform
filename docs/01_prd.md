# 产品需求说明文档（PRD）V1.0 最终版

**文档版本**：V1.0  
**拟定日期**：2026-08-22  
**文档状态**：已确认  
**核心目标**：构建一个配置驱动、带实时监控看板的浏览器自动化数据采集平台（RPA）。

---

## 1. 项目背景与目标

- **背景**：业务需要从多个不同的目标网站（URL）获取动态查询结果。这些页面交互复杂（涉及多条件筛选、下拉框、日期选择、分页），且部分站点需登录态（含验证码）。
- **目标**：开发一套“配置即采集”的系统。管理员在数据库配置好规则，系统模拟真实浏览器操作完成抓取，并提供轻量级可视化看板用于监控任务状态。

---

## 2. 用户角色

- **系统管理员**：负责在后台配置采集规则、通过看板管理登录态、查看任务进度及处理失败队列。

---

## 3. 功能需求详情

### 3.1 核心配置管理（一URL一配置，支持多输入框）

- **需求**：每个独立的业务页面拥有独立规则。因查询条件可能包含关键词、日期、下拉分类等多个控件，配置必须支持动态数量的输入框。
- **配置存储**：MySQL/PostgreSQL 表 `crawler_configs`。
- **核心配置字段**：

| 字段名                | 类型         | 说明                                     | 示例值                                                       |
| :-------------------- | :----------- | :--------------------------------------- | :----------------------------------------------------------- |
| `config_name`         | String       | 任务名称                                 | “商品价格监控”                                               |
| `target_url`          | String       | 目标页面地址                             | `https://x.com/search`                                       |
| `need_login`          | Boolean      | **是否需要登录**                         | `true` / `false`                                             |
| `auth_profile`        | String       | **登录态标识（站点名）**                 | `"taobao"` / `"jd"`                                          |
| `login_url`           | String       | 登录页面地址（`need_login=true` 时必填） | `https://x.com/login`                                        |
| **`input_configs`**   | **JSON数组** | **多输入框配置（核心）**                 | `[{"selector":"#kw","value":"{keyword}","type":"fill"}, {"selector":"#date","value":"2026-08-22","type":"fill"}]` |
| `submit_selector`     | String       | 查询按钮定位                             | `.search-btn`                                                |
| `wait_selector`       | String       | 数据加载完成标志元素                     | `.result-table`                                              |
| `fields_mapping`      | JSON         | 数据提取映射（支持`text`/`@href`）       | `{"订单号":".order-id text", "金额":".price text"}`          |
| `pagination_selector` | String       | “下一页”按钮定位（可选）                 | `.next-page`                                                 |
| `max_pages`           | Int          | 最大翻页页数（防死循环）                 | `10`                                                         |
| `is_active`           | Boolean      | 是否启用该配置                           | `true`                                                       |

> **input_configs 设计说明**：
> - `selector`：输入框/下拉框的CSS/XPath定位。
> - `value`：填入的值。支持硬编码或占位符（如 `{keyword}` 从任务表动态读取）。
> - `type`：操作类型（`fill`输入、`select`下拉选择、`check`勾选）。

---

### 3.2 登录态管理（多站点隔离 + 看板UI驱动）

- **策略**：采用“手动登录一次，复用长期凭证”策略，不破解验证码。
- **多站点隔离**：按 `auth_profile` 分别存储登录态文件（如 `auth_taobao.json`、`auth_jd.json`），互不干扰。公开页面（`need_login=false`）则启动匿名上下文。
- **看板UI驱动初始化（核心交互）**：
  1. 看板提供 **“登录态管理中心”** 面板。
  2. 管理员下拉选择 `auth_profile`，点击 **“更新登录态”**。
  3. 后端拉起**有头浏览器窗口**，跳转至该 `profile` 对应的 `login_url`。
  4. 管理员在弹出窗口中**手动完成登录**（含验证码）。
  5. 登录成功后，在看板点击 **“确认已登录并保存”**，后端自动保存 `auth_{profile}.json`。
  6. 看板实时展示每个 `profile` 的状态：`未配置` / `正常` / `已过期`。
- **运行时检测**：若 `need_login=true` 但文件缺失或跳转至登录页，任务暂停并在看板醒目告警：“请更新 [auth_profile] 登录态”。

---

### 3.3 自动化执行流程（串行）

- **数据源**：从数据库任务队列表（`job_queue`）动态获取待处理的关键词/参数列表（状态为 `pending`）。
- **串行执行逻辑**（单浏览器顺序处理，保证稳定）：
  1. 根据 `need_login` 加载对应登录态或匿名上下文。
  2. 访问 `target_url`。
  3. **遍历填充**：循环 `input_configs`，执行 `fill`/`select` 操作（支持占位符替换）。
  4. 点击 `submit_selector`，触发查询。
  5. 等待 `wait_selector` 出现（超时则报错）。
  6. **翻页循环**：若配置了 `pagination_selector`，循环点击“下一页”提取数据，直至无下一页或达 `max_pages`。
  7. 将提取的结构化数据存入结果表（`crawler_results`），并更新任务状态为 `success`。
  8. 处理 `job_queue` 中的下一个关键词（串行）。

---

### 3.4 数据持久化存储

- **存储对象**：提取到的业务数据（JSON格式）、原始查询参数、采集时间。
- **存储位置**：数据库 `crawler_results` 表；同时支持导出为本地JSON/CSV文件作为冷备份。

---

### 3.5 容错与失败重试机制（状态机驱动）

- **任务状态机**：`pending` -> `processing` -> `success` / `failed`。
- **跳过策略**：某关键词报错（超时、无数据、元素不存在）→ 捕获异常，状态置为 `failed`，记录错误日志，**跳过并继续处理下一个**，不阻塞队列。
- **定时补跑**：内置定时任务（如每30分钟），自动扫描 `failed` 且 `retry_count < 3` 的记录，重置为 `pending` 重新进入调度。

---

### 3.6 前端实时监控看板（纯状态监控）

- **通信方式**：WebSocket（实时推送）。
- **展示内容（严禁推送业务数据预览）**：
  - 当前正在处理的关键词/URL。
  - 总任务数与实时进度（如：已处理 45/100 条）。
  - 当前抓取页数（如：正在抓取第 3 页）。
  - 实时滚动日志（成功/失败/错误信息）。
  - 统计卡片：总任务数、成功数、失败数。
  - **登录态状态卡片**：展示所有 `auth_profile` 的状态（正常/失效/未配置）。

---

## 4. 非功能性需求

- **运行模式**：支持 `headless`（无头）模式运行，节省服务器资源（登录态更新时自动切换为有头模式）。
- **扩展性**：新增页面只需在数据库增加配置记录，**无需重启后端服务**。
- **稳定性**：单任务崩溃（如浏览器意外关闭）不影响主进程及看板WebSocket连接。

---

## 5. 约束与依赖

- **环境**：Python 3.9+、Playwright、MySQL/PostgreSQL、Node.js（前端静态服务）。
- **前置条件**：管理员需通过看板UI预先为各站点完成一次登录态保存。
