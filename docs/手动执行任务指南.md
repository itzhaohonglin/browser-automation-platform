## 方式 1: 通过 API 文档（推荐）

### ✅ 最简单、最直观的方式

### 步骤：

#### 1. 启动服务
```bash
.\startup.bat
```

#### 2. 打开 API 文档
在浏览器中访问：
```
http://127.0.0.1:8000/docs
```

#### 3. 找到任务执行接口
- 向下滚动找到 **"任务执行"** 标签
- 展开 `POST /task/run` 接口
- 点击 **"Try it out"** 按钮

#### 4. 填写参数
```
config_id: 1        # 必填，配置ID
limit: 1            # 可选，执行任务数量（1-10，默认1）
```

#### 5. 执行
点击蓝色的 **"Execute"** 按钮

#### 6. 查看结果
在 **"Response body"** 区域查看执行结果：
```json
{
  "status": "completed",
  "config_id": 1,
  "total_jobs": 1,
  "success_count": 1,
  "failed_count": 0,
  "results": [
    {
      "job_id": 123,
      "status": "success",
      "extracted_data": [...],
      "page_count": 5
    }
  ]
}
```

## 方式 2: 通过前端界面

### 步骤：

#### 1. 打开前端页面
```
http://127.0.0.1:8000/static/index.html
```

- 任务状态会自动更新
- 可以在 **"实时日志"** 面板查看执行过程

## 方式 3: 通过命令行

### 使用 curl 命令

#### 执行单个任务
```bash
curl -X POST "http://127.0.0.1:8000/task/run?config_id=1&limit=1"
```

#### 执行多个任务（最多10个）
```bash
curl -X POST "http://127.0.0.1:8000/task/run?config_id=1&limit=5"
```

#### 查看格式化输出（Windows PowerShell）
```powershell
Invoke-RestMethod -Method Post -Uri "http://127.0.0.1:8000/task/run?config_id=1&limit=1" | ConvertTo-Json
```

## 常见问题

### Q1: 提示"未找到待处理的任务"
**原因**：
- 该配置ID没有待处理（PENDING）的任务
- 所有任务都已执行完成或失败

**解决**：
1. 检查任务队列：访问 `http://127.0.0.1:8000/docs` 查看任务列表
2. 创建新任务：使用批量导入或手动创建
3. 重置已失败的任务状态

### Q2: 执行失败，显示浏览器驱动错误
**原因**：
- 未安装 Playwright 浏览器驱动

**解决**：
```bash
.\install_browser.bat
```

### Q3: 如何查看执行日志？
**方式 1**：查看日志文件
```
logs\app.log
```

**方式 2**：通过 WebSocket 实时查看
访问前端页面的 **"实时日志"** 面板

### Q4: 如何批量执行任务？
**方式 1**：调整 limit 参数（最大10）
```bash
curl -X POST "http://127.0.0.1:8000/task/run?config_id=1&limit=10"
```

**方式 2**：使用调度器自动执行
在配置管理中设置 `enable_scheduling: true`

## API 接口详细说明

### POST /task/run

**描述**：手动触发执行指定配置的待处理任务

**请求参数**：
- `config_id` (int, required): 配置ID
- `limit` (int, optional): 执行任务数量，范围 1-10，默认 1

**响应示例**：
```json
{
  "status": "completed",
  "config_id": 1,
  "total_jobs": 5,
  "success_count": 4,
  "failed_count": 1,
  "results": [
    {
      "job_id": 123,
      "status": "success",
      "extracted_data": [...],
      "page_count": 5
    },
    {
      "job_id": 124,
      "status": "error",
      "error": "timeout"
    }
  ]
}
```

**状态码**：
- `200`: 执行成功
- `404`: 未找到待处理任务
- `500`: 服务器内部错误

## 最佳实践

### ✅ 推荐做法

1. **测试新配置时**
   - 先用 `limit=1` 执行单个任务测试
   - 确认配置正确后再批量执行

2. **监控执行过程**
   - 打开前端页面的实时日志面板
   - 观察任务执行状态和错误信息

3. **定期检查结果**
   - 通过 API 或前端查看采集结果
   - 验证数据质量和完整性

### ❌ 避免做法

1. **不要同时执行大量任务**
   - limit 参数最大为 10
   - 避免对目标网站造成过大压力

2. **不要忽略错误信息**
   - 执行失败时查看详细错误
   - 根据错误调整配置

3. **不要在无头模式下调试**
   - 测试时设置 `HEADLESS_MODE=False`
   - 可以看到浏览器操作过程
