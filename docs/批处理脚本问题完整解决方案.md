## 根本原因

**双重问题**：

### 1. 编码问题（已解决）
- ❌ 原问题：批处理文件包含中文注释，UTF-8 编码在 Windows CMD 中乱码
- ✅ 解决：移除所有中文注释，使用纯英文

### 2. 行尾符问题（已解决）
- ❌ 原问题：文件使用 Unix 格式（LF），Windows 批处理需要 DOS 格式（CRLF）
- ✅ 解决：使用 `unix2dos` 工具转换所有 .bat 文件为 CRLF 格式

## 技术细节

### 行尾符对比

| 格式 | 行尾符 | 十六进制 | 适用系统 |
|------|--------|---------|---------|
| Unix/Linux | LF | `0x0A` (\n) | Linux, macOS |
| Windows/DOS | CRLF | `0x0D 0x0A` (\r\n) | Windows |

### Windows 批处理要求
- **必须使用 CRLF** - Windows CMD 只识别 CRLF 作为行结束符
- **使用 LF 会导致**：
  - 命令解析错误
  - 出现乱码字符
  - "命令不存在"错误

### 为什么会出现 LF 格式？
- Git 在 Linux/macOS 环境下默认使用 LF
- 使用 Write 工具创建文件时默认使用 LF
- 某些文本编辑器（如 VS Code）默认使用 LF

## 预防措施

### 方法 1：Git 配置（推荐）
在项目根目录创建 `.gitattributes` 文件：
```
# .gitattributes
*.bat text eol=crlf
*.cmd text eol=crlf
```

这样 Git 会自动处理批处理文件的行尾符。

### 方法 2：编辑器配置
如果使用 VS Code，在 `.vscode/settings.json` 中添加：
```json
{
  "files.eol": "\r\n",
  "[bat]": {
    "files.eol": "\r\n"
  }
}
```

### 方法 3：提交前检查
```bash
# 检查所有批处理文件的格式
find . -name "*.bat" -exec file {} \; | grep -v "CRLF"

# 如果有输出，说明需要转换
find . -name "*.bat" -exec unix2dos {} \;
```
